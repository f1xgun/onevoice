# Roadmap: v1.4 Launch Readiness (Free Beta)

**Status:** 📋 Planned
**Source:** Synthesized from 5-agent audit (2026-05-24) — see `LAUNCH-AUDIT-2026-05-24.md`
**Target duration:** 2–3 weeks
**Prerequisite:** Close v1.3 (Chats & Projects) formally before starting

## Milestone Goal

Close every P0 blocker found in the launch-readiness audit so the first 5–10 real businesses can use OneVoice end-to-end without hitting a 404, a brick wall, or a legal violation — while the product is still free.

This milestone is NOT about taking money (that's v1.5). It's about making the product safe to put in front of real users.

## Definition of Done

1. A first-time visitor can register → verify email → reset password if forgotten → create business → connect integration → chat with agent → delete their account — every step works in the UI without dev intervention.
2. Privacy Policy + ToS published; consent checkbox at registration captures explicit agreement (152-ФЗ Art. 9 compliant).
3. A clean `migrate up` on a fresh database succeeds.
4. PG + Mongo nightly backups run automatically with off-host upload and a documented restore procedure that has been tested at least once.
5. Grafana is not protected by default credentials and the observability stack is not internet-reachable on a public port.
6. LLM cost-per-conversation is bounded (`RateLimiter` enforced, `DailySpendUSD` honored) and accurate (real costs in `UsageLog`, not `$0`).
7. Account lockout or captcha exists on login after N failed attempts.
8. `/health/ready` correctly fails when PG / Mongo / Redis / NATS are down.

## Out of Scope (deferred to v1.5+)

- Payment provider integration (YooKassa) — v1.5
- Subscription lifecycle, plan tiers, billing UI — v1.5
- 54-ФЗ fiscal receipts, ИНН/КПП/УПД — v1.5
- Conversation-per-business sharing decision — v1.6 (needs UX design)
- Optimistic concurrency on shared edits — v1.6
- LLM `ChatStream` for terminal turn (UX polish) — v1.4 stretch
- OpenTelemetry tracing — backlog

## Phases

### Phase 20: Critical Onboarding & Migration Fixes
**Goal:** A new user can complete onboarding without dead ends, and a fresh DB migrates cleanly.
**Depends on:** Nothing
**Severity:** P0
**Success Criteria:**
1. `/business/new` page exists on `main` and `POST /api/v1/businesses` is reachable from it (`useBusinessList` mutation wired).
2. Duplicate migration version `000008` renumbered (`audit_log_infrastructure` → `000009`, then renumber subsequent — keep both `migrations/postgres/` and `services/api/migrations/` consistent per [project_migration_dual_path]).
3. Posts page "Create post" button either wired to chat-with-prefill or hidden (no dead UI).
4. Google Business integration shown as "Preview" or "Beta" in `/integrations` until tools 3–11 actually wire end-to-end (currently only 2 of 11 routed in `agent-google-business/internal/agent/handler.go`).
**Expected plans:** 3
**UI hint:** yes

### Phase 21: Account Lifecycle
**Goal:** Users can recover access, prove email ownership, and delete their data.
**Depends on:** Phase 20
**Severity:** P0 (blocks any paying user)
**Success Criteria:**
1. `POST /auth/password-reset/request` → email with single-use, time-bound token → `POST /auth/password-reset/confirm` completes reset. Audit-logged.
2. Registration sends verification email; unverified accounts cannot connect integrations or send chat (soft restriction with banner).
3. `DELETE /users/me` endpoint hard-deletes user; business deletion follows last-owner rules already in DB trigger (`migrations/postgres/000007_rbac_data_model.up.sql:117-144`). 30-day soft-delete grace window per 152-ФЗ Art. 21.
4. Email sending infrastructure (SMTP or Mailgun/Postmark) added with retry queue.
**Expected plans:** 4
**UI hint:** yes

### Phase 22: Legal Compliance Scaffolding
**Goal:** OneVoice can legally operate as a Russian PD operator.
**Depends on:** Nothing (parallel-safe with Phase 21)
**Severity:** P0
**Success Criteria:**
1. `/legal/privacy` and `/legal/terms` pages published (Russian, both routes addressable, version-stamped).
2. Registration form has consent checkbox referencing Privacy Policy, with explicit "Я согласен на обработку персональных данных" — captured to `user_consents (user_id, policy_version, accepted_at)` table.
3. Footer of every page links to Privacy Policy and Terms.
4. Data-controller block (legal name, ИНН, contact email for ПДн requests) rendered in Privacy Policy and `/legal/contact`.
5. Documented checklist for Роскомнадзор `Уведомление об обработке ПДн` filing (operator does this outside code — checklist is the deliverable).
**Expected plans:** 3
**UI hint:** yes

### Phase 23: Operational Hardening
**Goal:** First production incident is recoverable; the system fails loudly, not silently.
**Depends on:** Nothing (parallel-safe)
**Severity:** P0
**Success Criteria:**
1. `scripts/backup.sh` runs `pg_dump` + `mongodump`, uploads to S3-compatible Yandex Object Storage with 30-day retention; cron unit in `docker-compose.observability.yml` or systemd; `docs/runbook-restore.md` written and verified by one full restore-from-backup drill.
2. Grafana default `admin/admin` replaced by env-injected strong password; observability stack `docker-compose.observability.yml` bound to internal network only (or nginx-basic-auth-fronted).
3. `health.AddCheck` calls registered for PG, Mongo, Redis, NATS — `/health/ready` returns 503 when any dependency is down.
4. Login endpoint: account lockout (15 min after 10 failed attempts per email) OR Hcaptcha challenge after 3 failures. Configurable via env.
5. Frontend "Create post"-style buttons localized; English error strings in `services/api/internal/handler/auth.go:183,191,273,323,355,393,437` replaced with error codes mapped through `error_mapping.go` pattern.
**Expected plans:** 4
**UI hint:** partial

### Phase 24: LLM Quality & Streaming Wins
**Goal:** Russian-language chat quality jumps a generation and first-token latency drops from seconds to ~200ms.
**Depends on:** Nothing
**Severity:** P1 (huge quality + cost win, not strictly a blocker)
**Success Criteria:**
1. `LLM_MODEL` default changed to `anthropic/claude-sonnet-4-6` in `.env.example` and both `docker-compose.yml` overrides; `claude-haiku-4-5` set as cheap fallback for `draft_reply` and title generation.
2. Anthropic prompt caching enabled: `CacheControl: anthropic.NewCacheControlEphemeralParam()` applied to system prompt block and tool definitions in `pkg/llm/providers/anthropic.go:80-94`. Measure: cache hit rate ≥ 90% on conversation turns 2+; input cost down ≥ 60% on a 5-iteration test.
3. Anthropic provider implements tool-calling (currently `providers/anthropic.go` drops `req.Tools` — agent loop only works via OpenRouter/OpenAI today).
4. Stale `HealthCheck` model ID and `ListModels` enum in `providers/anthropic.go:37,55-77` refreshed to current Claude 4.6/4.7 IDs.
5. Stretch: orchestrator switches to `ChatStream` for terminal text turn (`services/orchestrator/internal/orchestrator/step.go:106`) — user sees first token within 500ms.
**Expected plans:** 3
**UI hint:** no (visible only as latency)

### Phase 25: LLM Cost Guards & Billing Substrate
**Goal:** Cannot lose money to a runaway agent loop. Usage is tracked accurately per business — even though we're not yet charging.
**Depends on:** Phase 24 (after model swap, costs are real)
**Severity:** P0 (currently zero defense against $1000/day OpenRouter spend per memory: `Async billing: go r.logBilling(...) — fire-and-forget` writes to nothing)
**Success Criteria:**
1. `PostgresBillingRepository` implementing `pkg/llm/billing.go:64-77 BillingRepository` lands; `usage_logs` migration in **both** migration paths (`migrations/postgres/` + `services/api/migrations/`); fields include `business_id`, `user_id`, `conversation_id`, `request_id`, `model`, `provider`, input/output tokens, cost USD, commission USD, created_at.
2. `services/orchestrator/cmd/main.go` wires `llm.WithBilling(...)` and `llm.WithRateLimiter(...)` into the router.
3. `ModelProviderEntry` populated with real `InputCostPer1MTok` / `OutputCostPer1MTok` in `wire/llm.go:60-65` so `UsageLog` is not always `$0`.
4. `BusinessID` propagated through `ChatRequest` (`pkg/llm/types.go:50`) from `chat_proxy.go:394` (currently hardcoded `"tier": ""`).
5. `RateLimiter.CheckLimit` enforces `DailySpendUSD` (currently field declared, never read at `pkg/llm/ratelimit.go:80-148`).
6. Per-conversation token cap (e.g. 50k input + 10k output) in `orchestrator/step.go` — stop and surface friendly SSE error before runaway.
7. `MaxTokens` set on agent-loop LLM calls in `step.go:99-105` (currently unset — Anthropic 400s on missing, OpenAI runs to model limit).
8. Router retries once on transient 5xx / 429 from one provider on a sibling entry (`pkg/llm/router.go:127-132`).
**Expected plans:** 5
**UI hint:** no (operator-facing dashboards instead)

### Phase 26: Concurrency Limits & Platform Failure UX
**Goal:** A single abusive user cannot OOM the server. When a platform token dies, the user sees an actionable message, not a generic error.
**Depends on:** Phase 23
**Severity:** P1
**Success Criteria:**
1. `services/orchestrator/internal/handler/chat.go` enforces N concurrent SSE streams per user (default 3); excess returns 429.
2. `BrowserPool` (`services/agent-yandex-business/internal/yandex/pool.go:27-52`) bounded by max-contexts cap (default 10); LRU eviction beyond cap.
3. `pgxpool` `MaxConns/MinConns/MaxConnLifetime` tuned via env in `services/api/internal/wire/databases.go:101`.
4. Frontend `/tasks/page.tsx:55-100` error matcher refactored to read **error codes** from the response, not regex on free text.
5. When agent emits `tool_error` with `code=integration_token_invalid`, the chat surface shows inline "Переподключить Telegram" CTA (currently only in Tasks page).
**Expected plans:** 4
**UI hint:** yes (chat + tasks)
