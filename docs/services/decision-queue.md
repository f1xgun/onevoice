The decision queue is a read projection over existing reviews, pending approval batches, integration health and card comparisons. Each source keeps its permission check. Approval batches are selected by business and requesting user; a batch remains one decision with its original conversation link and action count. Its display context contains recognized destination platforms, a bounded text excerpt and a common scheduled time only when every action has that same time. Tool arguments and provider coordinates are not part of the excerpt projection.

Automatic receipts come only from successful `review.auto_replied` audit events. The queue joins the event target to the same business’s review only when the caller can read content. This supplies the author, rating or recognized factual-question kind for display. Personal review data is not added to audit events or telemetry. Missing/deleted reviews and callers without content access receive the platform-level receipt without personal context.

Inbox actions use the existing review send/retry/skip/regenerate routes and the existing conversation creation and streaming flow for new instructions. A failed instruction retains its text and reuses the created conversation on retry. The reply form shows the exact text being submitted, with an existing reply signature separated into its own paragraph.
