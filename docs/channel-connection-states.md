# Состояния каналов

Контракт проверен по исходникам на базе `8d4b6128` (8 сентября 2026).
Sidebar и карточки интеграций используют одну функцию
[`channelConnectionState`](../services/frontend/lib/constants/integrationStatus.ts).
Ошибка загрузки списка не подтверждает поломку ни одного канала.

## Источники фактического контракта

- [`ListIntegrations`](../services/api/internal/handler/integration.go) возвращает
  `GET /api/v1/businesses/{id}/integrations` как `200` + массив без обёртки.
  При ошибке чтения — `500 {"error":"internal server error"}`;
  [общий сериализатор ошибок](../services/api/internal/handler/response.go) использует
  строковое поле `error`, а не вложенный объект из общего примера в api-design.md.
- [`Integration`](../pkg/domain/models.go) задаёт camelCase полей
  `businessId`, `externalId`, `createdAt`, `updatedAt`, необязательного `tokenExpiresAt`.
  Токены исключены из JSON. Схема
  [`Integration` в OpenAPI](api/spec/openapi.yaml) оставляет `status` строкой,
  без enum. Это не гарантирует, что произвольная строка имеет известную семантику.
- [`integration_status.go`](../pkg/domain/integration_status.go) содержит два
  сохраняемых статуса: `active` после подключения/восстановления доступа и
  `token_expired` после подтверждённого отказа площадки в доступе.
  [`MarkTokenExpired`](../services/api/internal/service/integration.go) обрабатывает
  подтверждённое событие отказа. Сравнение локальных часов с `tokenExpiresAt`
  не используется для объявления ошибки подключения.
- [`activeQuery` и `ListByBusinessID`](../services/api/internal/repository/integration.go)
  фильтруют по `deleted_at IS NULL`, не по `status=active`.
  Поэтому список содержит и `token_expired`; отключение мягко удаляет запись,
  а не присваивает ей `inactive`. Успешный пустой список — `[]`.
- [`connhealth/health.go`](../services/api/internal/service/connhealth/health.go)
  задаёт отдельный объект `metadata.connection_health` с полями `status`,
  `reason_code`, `checked_at` (snake_case). `broken` — подтверждённая неисправность,
  `unknown` — неопределённая проверка; `degraded` зарезервирован для частичного
  ограничения возможностей, сейчас штатные проверки его не выставляют.
  `DemoteOnlyIfConclusive` сохраняет предыдущий определённый результат при
  неопределённой повторной проверке. При этом `checked_at` продвигается: это
  время попытки проверки, не гарантия свежего подтверждения работоспособности.
- [`connhealth/checker.go`](../services/api/internal/service/connhealth/checker.go)
  не считает таймаут, ограничение частоты или ненастроенную проверку поломкой.
  `POST .../integrations/verify` также запускает внешнюю повторную отправку
  профиля; для чтения статусов он не вызывается. Его ответ `202` использует
  отдельную схему `health[]` с `reasonCode`/`checkedAt`, не форму metadata.
- `PlatformStatus` в `lib/api/platforms.ts` описывает каталог площадок
  (`active`, `coming_soon`, `oauth_not_configured`), а не подключение организации.
  Он не служит доказательством состояния канала.

## Таблица соответствия

Перед вычислением состояния выбирается организация и её список интеграций.
При отсутствии выбранной организации интерфейс предлагает её выбрать;
это не запрос в состоянии loading и не свидетельство disconnected.

| Ответ API / состояние запроса                                                              | Состояние          | Отображение                                                                                                                |
| ------------------------------------------------------------------------------------------ | ------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| Первый запрос ещё выполняется, данных нет                                                  | `loading`          | Sidebar: «Проверяем подключение»; страница: доступный скринридеру скелет загрузки                                          |
| Успешный `200 []`, либо в успешном массиве нет записей этой площадки                       | `disconnected`     | «Не подключено»; в sidebar — переход к настройке через «Интеграции»                                                        |
| `200`, запись с `status: "active"`, health отсутствует или имеет `active`                  | `connected`        | «Подключено»                                                                                                               |
| `200`, `status: "active"`, health имеет `unknown` / отсутствующее или неизвестное значение | `connected`        | Последнее подтверждённое подключение сохраняется; неопределённая проверка не создаёт тревогу                               |
| `200`, `status: "active"`, health имеет `degraded`                                         | `connected`        | «Подключено», в строке канала дополнительно «Ограничено»; это не полный отказ                                              |
| `200`, `status: "token_expired"`, независимо от health                                     | `error`            | «Ошибка подключения», в строке — причина и существующая ссылка переподключения                                             |
| `200`, `metadata.connection_health.status: "broken"`, независимо от статуса записи         | `error`            | «Ошибка подключения», описание подтверждённой причины; зелёное «Подключено» не показывается у этой строки                  |
| Запись есть, но `status` отсутствует, пуст или неизвестен; нет подтверждённого отказа      | `unknown`          | Нейтральное «Статус пока неизвестен», без переподключения по одному отсутствию данных                                      |
| Старые/неподдерживаемые строки `inactive`, `error`, `pending_cookies` без health `broken`  | `unknown`          | В текущем сервере нет писателя этих статусов; не выдаём их за подтверждённое отключение/поломку                            |
| Ответ отсутствует после завершения запроса; `null`, объект вместо массива                  | `unknown`          | Нейтральное неизвестное состояние; на странице можно повторить чтение списка                                               |
| Не удалось прочитать список: HTTP 401/403/500, сеть/таймаут                                | `unknown`          | «Статус каналов пока неизвестен» + пояснение о загрузке списка и кнопка «Повторить»; это ошибка чтения, не диагноз каналов |
| Фоновый запрос идёт при наличии прежнего успешного списка                                  | По прежнему списку | Не заменяем известное состояние загрузкой                                                                                  |
| Фоновое обновление списка завершилось ошибкой, данные остались в кэше                      | `unknown`          | Старые данные не выдаются за актуально подтверждённый ответ; красной ошибки канала нет                                     |

Несколько каналов одной площадки учитываются все, независимо от порядка ответа:
подтверждённая ошибка хотя бы одного даёт сводный `error`; иначе неизвестная
запись даёт `unknown`; иначе непустой список активных каналов даёт `connected`.
Сводный `error` не означает, что сломаны все каналы: карточка сохраняет отдельные
статусы и причины для каждой строки. Пустой список даёт `disconnected` только
после успешного ответа, а не в результате подстановки `[]` вместо ещё не полученных данных.

## Fixtures и проверки

[`channel-responses.json`](../services/frontend/test/fixtures/channel-responses.json)
фиксирует HTTP-коды и JSON тела по фактическим сериализаторам и схеме:
`empty`, `active`, `tokenExpired`, `broken`, `inconclusive`, `healthy`,
`degraded`, `listFailure`. Это воспроизводимые примеры контракта с вымышленными
ID и именем канала, не запись запросов к живому стенду. `degraded` проверяет
зарезервированную ветку контракта. Неподдерживаемые строки и неправильные формы
ответа задаются отдельно в тестах и не выдаются за ответы штатных серверных писателей.

Тесты проверяют:

- [`connectionStatus.test.ts`](../services/frontend/components/sidebar/__tests__/connectionStatus.test.ts):
  таблицу, отсутствие данных, все записи площадки и независимость от порядка.
- [`PlatformStatus.test.tsx`](../services/frontend/components/sidebar/__tests__/PlatformStatus.test.tsx):
  видимые подписи ru/en и нейтральное оформление неопределённости.
- [`NavRail.test.tsx`](../services/frontend/components/sidebar/__tests__/NavRail.test.tsx):
  использование полного списка площадки в sidebar.
- [`PlatformCard.test.tsx`](../services/frontend/__tests__/PlatformCard.test.tsx):
  отсутствие противоречивого «Подключено» при broken, подписи неизвестных
  статусов, неопределённая проверка и частичное ограничение.
- [`channelStatus.test.tsx`](<../services/frontend/app/(app)/integrations/__tests__/channelStatus.test.tsx>):
  страницу с реальными дочерними компонентами и подменой HTTP на границе;
  сбой списка, повтор до `200 []`, неправильные формы ответа, загрузку и выбор организации.

Серверные писатели и API-схемы не изменяются. Live-проверки площадок,
перезапуск стенда и внешние действия не нужны для воспроизведения этих тестов.
